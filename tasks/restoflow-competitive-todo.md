# RestoFlow Competitive Roadmap - Task List

هذه القائمة مستقلة عن tasks/plan.md الخاص بالـ Theme Engine.

## نطاق التنفيذ الحالي

التكاملات الخارجية والشراكات (Paymob، Talabat، وأي منصة مشابهة) مؤجلة مؤقتًا. لا نضيف probes أو live adapters جديدة لها الآن؛ نركز على جودة المنتج الداخلية، التشغيل Offline، الأجهزة، التحديث/الاسترجاع، Customer 360، الطلب العام، والتنبؤات. البنود الموجودة عن التكاملات محفوظة كـ backlog ولا تُعامل كأولوية تنفيذ حالية.

- [x] Offline payment safety — تم منع أي non-cash order من دخول queue أو replay، واختبارات Offline المركزة 29/29، وunit gate الكامل 243/243 ملفًا و545/545 اختبارًا.
- [x] Hotfix installer compatibility — launch gate يهاجر أسرار الإنتاج الناقصة في `.env` مع backup، health check يقرأ `API_PORT`، وحزمة 1.1.40 تحققت من 8,576 ملفًا.
- [x] Day-close connectivity guard — منع بدء إغلاق اليوم أو تغيير business date أثناء Offline، مع إبقاء مسار Online كما هو واختبارين للسلوك.

## Phase 2 - Offline
- [~] 2.1 كتابة Offline Contract — تم توثيق عقد queue الرسمي في `docs/offline-sync-contract.md` ويغطي branch binding وdedupe وretry/backoff وlease recovery وconflict quarantine؛ وتم fail-closed للـunsupported actions وحدود الدفع (النقد فقط، وSplit نقدي بالكامل)، ومنها branch creation online-only، وتنفيذ Warehouse UPDATE/DELETE بدل تعليمها Synced بلا API، مع replay tests فعلية لكل adapters الحالية (menu/inventory/warehouse/stock/customer/order/status/table/settings/audit) ضمن suite المعزولة؛ وأصبح replay يتحقق من branch envelope وpayload معًا قبل استدعاء أي adapter، و409 الخاص بـ`IDEMPOTENCY_KEY_PAYLOAD_CONFLICT` أو أخطاء الأعمال مثل `WAREHOUSE_INACTIVE` لا تُخفى كنجاح، واختبار recovery يثبت إعادة استخدام نفس المفتاح مع أثر خادم واحد؛ ما زالت duplicate/conflict assertions المتخصصة لكل domain ومصفوفة التشغيل الكاملة مطلوبة
- [~] 2.2 local branch runtime — كل Queue Item جديد يحمل `branchId` مستقلًا، ومفتاح dedupe أصبح branch-aware، والمزامنة تُرشّح الفرع النشط وتمنع mismatch؛ replay والـcentral deployment commands يتحققان من branch envelope وpayload قبل التنفيذ أو acknowledge؛ وclaim الـqueue أصبح read-check-update ذريًا داخل Dexie transaction، وأثبت اختبار IndexedDB فعلي باتصالين مستقلين أن duplicate claim لا يحدث؛ الطباعة المحلية للطابعات `LOCAL/WINDOWS/USB` تعمل عبر loopback bridge أثناء Offline، بينما `NETWORK/LAN` تبقى server-queued؛ أضيف KDS fallback يقرأ الطلبات غير المتزامنة من IndexedDB حسب الفرع، وlocal hub فوري عبر `BroadcastChannel` مع storage fallback، وBump/Recall المحليان يدخلان queue؛ العناصر legacy غير المرتبطة تتحول إلى Conflict للمراجعة، وما زال الربط بين أجهزة فعلية عبر LAN وserver restart/UAT الحقيقي مطلوبًا
- [~] 2.3 recovery وconflict center — stale locks تُستعاد، والـconflicts تظهر في notifications مع `resolveConflict`، وتم تقييد الإحصاءات وواجهة Conflict Center بالفرع النشط؛ أضيف `MERGE` محافظ بأولوية server مع زر Safe merge وعقد موثق، وكل resolution يضيف `OFFLINE_CONFLICT_RESOLVED` audit event branch-bound إلى queue؛ وأصبحت Queue Health تعرض `pending/failed/conflicts/synced` للفرع النشط فقط مع اختبار عزل؛ وأصبحت أخطاء branch/auth/unsupported/business (401/403/409/422) تُعزل كـ`CONFLICT` بدل retry أعمى، مع مسح `nextAttemptAt` عند quarantine حتى لا تعود للجدولة، بينما تبقى أخطاء الشبكة/الخادم transient؛ ما زالت إثباتات integration وmerge rules المتخصصة لكل domain مطلوبة
